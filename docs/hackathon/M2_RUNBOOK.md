# M2 — Muse Spark tool-using advisory agent

**Status:** implementation candidate; reviewed offline. Not a closed milestone until the owner's repository CI and live smoke evidence exist.

## Scope

EDEN Grid Sentinel M2 adds an optional, bounded Chat Completions adapter for Meta Model API using `muse-spark-1.3`. The model requests the **single allowlisted, read-only** `get_simulation_summary` tool. The adapter validates its name, JSON arguments, scenario identity, call ID, and quantity. The trusted, deterministic M1 digital twin computes the actual evidence. The model returns a JSON-schema-constrained advisory; the adapter independently validates and attaches M1-computed numbers.

This **does not** implement forecast prediction (M3), optimization (M3), autonomous actuators, Guardian policies or approvals (M4), dashboards (M5) or measured energy data.

## Why Chat Completions for M2?

Meta's documented Chat Completions protocol supports an OpenAI-compatible SDK, function tools and JSON-schema structured output. **As documented on October 30, 2026, Meta supports only `tool_choice="auto"`, not `"required"`, so absence of a tool call is treated as a protocol failure**. The tool-calling assistant message must be replayed before the tool response; the code enforces this. No model reasoning chain is persisted. If long-horizon agent reasoning becomes necessary, evaluate Responses API in a separately reviewed future milestone.

References:
- https://dev.meta.ai/docs/cookbook/tool-function-calling
- https://dev.meta.ai/docs/cookbook/structured-output
- https://dev.meta.ai/docs/protocols/chat-completions

## Operational boundaries and safeguards

1. `assess_scenario()` accepts only the three existing fixed M1 fixture names. It does **not** accept arbitrary prompts, file paths, URLs or equipment commands.
2. Exactly one tool call is allowed; no multi-call loop. The tool only returns local simulated data.
3. Maximum two logical model turns, with up to one retry for transient failures per turn (at most four provider calls). SDK automatic retries are disabled.
4. Token ceilings: 768 (tool turn) and 1024 (final assessment) including reasoning. Final output uses the strict JSON-schema format.
5. Any invalid tool name, duplicate arguments, wrong fixture, missing tool call, malformed JSON or unexpected final call fails closed.
6. Numeric evidence is generated by M1, not trusted from model output. All results are labeled `simulation` and `advisory_only`.
7. No API endpoint for generating paid requests is exposed. `scripts/m2_live_smoke.py` requires BOTH `--live` and `--confirm-billing` before making any call.
8. No file persistence, secret printing or raw provider exception logging in this module. `store=False` is sent on both provider requests.
9. This module has NO permission to control real or simulated equipment: planning and execution remain separate later milestones.
10. No network access happens on module import or during fake-client tests.

**Limitations:** JSON schema validation constrains shape, not the factual accuracy of the model's natural language explanations. A reviewer must still verify recommendations and ensure they do not claim physical savings. M2 cannot itself calculate an optimal plan.

## Windows setup

Base M1 branch: `feat/m1-microgrid-digital-twin` (draft PR #1, head at time of preparation `aa3cf08ffc22471f3407d99f300dcaf70f5ddd64`). Create a separate M2 branch **from M1**, not `main`, while PR #1 is unmerged:

```powershell
git fetch origin
git switch feat/m1-microgrid-digital-twin
git pull --ff-only origin feat/m1-microgrid-digital-twin
git switch -c feat/m2-muse-spark-integration
```

Apply the M2 overlay contents from the ZIP into the repository root, preserving the relative paths and replacing none of the inherited M1 simulator files. If your repo differs from the documented M1 branch, review the patch manually before copying.

Python 3.11/3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[pipeline,dev]"
python -m pip install "openai>=2.0,<3"
python -m pytest -q
```

Add the reproducible optional dependency to `[project.optional-dependencies]` in `pyproject.toml` when committing:

```toml
meta = ["openai>=2.0,<3"]
```

Once saved, you can use `python -m pip install -e ".[pipeline,dev,meta]"` on clean environments.

## Offline demonstration — zero billable requests

```powershell
python scripts/m2_live_smoke.py --scenario cloudy_school_day
python scripts/m2_live_smoke.py --scenario night_reserve
```

This prints only deterministic M1 fixture summary, labeled `offline_fixture`. It is **not a mock claim that Muse Spark answered**. The fake-client test cases exercise the agent tool protocol without contacting Meta.

## Opt-in live smoke — could incur charges

**Required precondition:** Revoke/rotate any `MODEL_API_KEY` that was ever checked in under `.env.example` (even if removed from the branch), and use a new key. Confirm usage budget, current pricing, access limits, and your participation rules first.

Set a *new* API key in the environment (never in files, messages, Git logs or shell history). For example, use the secret prompt in the established `MUSE_CODE_SETUP.md` rather than `setx` or an inline literal.

```powershell
python scripts/m2_live_smoke.py --scenario cloudy_school_day --live --confirm-billing
```

A successful live run prints a structured model-generated advisory plus a trusted M1 simulator summary. It does not publish to cloud, update Git, or actuate anything. It does not log token counts; view exact usage/billing in the Meta dashboard. Model failures return a sanitized error and a nonzero exit status.
